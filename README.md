# 🐘 Elephant Tavern

SillyTavern как настоящее Android-приложение. Внутри APK — полноценный SillyTavern 1.19
на встроенном Node.js 24 (без Termux и без ПК), поверх — мобильный интерфейс, который
живёт вместе с историей, автоматические иллюстрации через NanoGPT и память Elephant Memory
из коробки.

## Что внутри

| Слой | Где | Что делает |
|---|---|---|
| **Android-оболочка** | `app/` | Kotlin + JNI. Node.js (nodejs-mobile) запускает SillyTavern в отдельном процессе `:node` с foreground-сервисом, поэтому генерация не обрывается, когда приложение свёрнуто. WebView открывает `127.0.0.1`. Бэкап и восстановление, лог сервера, кнопка «назад», вибрация, сохранение в «Загрузки». |
| **Форк SillyTavern** | `tavern/SillyTavern` | Исходники SillyTavern 1.19.0, правятся прямо здесь. Фронтенд-библиотеки собираются заранее, поэтому сервер стартует за секунды. |
| **Elephant Core — сервер** | `tavern/SillyTavern/src/elephant` | `/api/elephant/*`: служебная модель NanoGPT с сохранённым ключом (профиль Connection Manager не нужен, запрос не обрывается, если WebView уснул), список моделей с ценами, планировщик «пишет первым» и входящие. |
| **Elephant Core — клиент** | `tavern/SillyTavern/public/scripts/elephant` | Часть приложения, а не расширения: стартует из `script.js` вместе с таверной. Модули: `memory` (Elephant Memory), `stage`, `game`, `proactive`, `chat`, `welcome`, `power`, `forge`. Генерация вызывает ядро напрямую (`runGenerationInterceptors`): сначала память, потом игровой движок. |

Точки, где ядро вшито в SillyTavern: `public/script.js` (запуск ядра), `public/scripts/extensions.js` (хук генерации), `src/server-startup.js` (роутер `/api/elephant`), `public/index.html` (стили ядра), `webpack.config.js` (готовый фронтенд).

### 🎭 Elephant Stage

- **Мобильная оболочка.** Компактная шапка с аватаром, именем и текущей сценой; хаб со
  всеми разделами SillyTavern плиткой; шторки снизу со свайпом; пузыри сообщений;
  поле ввода-«пилюля». Кнопка «назад» закрывает шторку → попап → панель, и только потом
  сворачивает приложение.
- **Сцена управляет интерфейсом.** После каждого ответа сцена читается — мгновенно по
  ключевым словам (EN/RU), затем уточняется дешёвой служебной моделью (JSON: настроение,
  погода, время суток, место, события). От этого меняются:
  - палитра всего интерфейса и цвет прямой речи (10 настроений: спокойно, уютно, радость,
    романтика, напряжение, бой, тайна, жуть, грусть, эпично);
  - частицы на фоне: дождь, гроза, снег, туман, пепел, светлячки, звёзды, угольки,
    лепестки, искры магии;
  - события: удар → тряска экрана, красная вспышка, искры и вибрация; взрыв, молния,
    поцелуй (сердечки + сердцебиение), магия, кровь. Удары ловятся ещё во время стриминга.
  - Настроение можно закрепить вручную (тап по чипу настроения в шапке).
- **Картинки NanoGPT.** Два вида кадров:
  - **POV** — сцена глазами `{{user}}`, персонаж перед камерой, тебя не видно;
  - **Портрет** — фокус на персонаже: лицо/по пояс, эмоция и одежда этого момента.

  Служебная модель один раз собирает «ДНК внешности» персонажа из карточки (теги, которые
  держат его узнаваемым; редактируются руками), а для каждого кадра пишет промпт из ДНК,
  карточки состояния Elephant Memory и последних сообщений. Картинка уходит через
  эндпоинт SillyTavern `/api/sd/nanogpt` (тот же ключ NanoGPT, что и для чата),
  сохраняется в галерею персонажа и прикрепляется к сообщению. POV-кадр становится
  размытым фоном чата. Авто-режим: при смене сцены или каждые N ответов; кнопки 👁 и 🖼 на
  каждом сообщении, камера в шапке.

Команды: `/stage-pov`, `/stage-portrait`, `/stage-mood romance|auto`, `/stage-fx hit`.

### 🎲 Elephant Game — игровой режим

Включается для каждого чата отдельно: хаб → **Игра**. Принцип: **движок считает, модель рассказывает**.

- **Судья** (дешёвая модель, перед ответом) решает, нужна ли проверка. Простой разговор
  судью не вызывает вовсе: проверка нужна только действиям (`*в звёздочках*` или со словами
  вроде «вскрываю», «вру», «атакую»).
- **Карточка проверки:** навык, позиция (под контролем / рискованно / отчаянно), сложность,
  точный шанс, угроза, которую питает провал. Можно «надавить» (+1 к броску за стресс)
  или отменить ход. 2d6 + навык и пять исходов: блестяще, успех, успех ценой, провал,
  катастрофа. Провал двигает историю, а не останавливает её.
- **Рассказчик** получает на глубине 0 короткий блок `[GAME ENGINE]` с состоянием и
  исходом и пишет по нему, не называя механику.
- **Учётчик** (тот же дешёвый вызов, что читает сцену для Stage) после ответа сообщает,
  что изменилось: время, место, доверие и влечение NPC (с ограничением шага), деньги,
  вещи, цели, часы.
- **HUD** заменяет строку трекера `[🕐 | 📍 | 🌤]`: время, место, погода, деньги, раны,
  стресс и двое ближайших часов. Тап открывает лист: герой и навыки с прокачкой, связи,
  цели и часы, журнал бросков.
- Раны (3 уровня со штрафами), стресс до 9, опыт за провалы и цели, уровни. При смертельной
  ране — выбор: «выжить ценой» (шрам) или «откатиться».
- Состояние снимается на каждое сообщение, поэтому свайп не перебрасывает кубики, а удаление
  и правка откатывают игру сами.

Команды: `/game`, `/game-roll finesse 8 pick the lock`.

### 📩 Персонаж пишет первым

Выключено по умолчанию. Включается в «Сцена и арт» для каждого персонажа отдельно: частота (после суток, ~8 или ~3 часов тишины), тихие часы,
модель. Сервер работает в фоне, пока в шторке висит «Сервер работает»: после паузы он пишет
короткое сообщение в характере (подхватывает обещания и незакрытые нити из памяти) и присылает
уведомление с аватаром. Тап открывает чат, сообщение уже в нём. Больше двух подряд без ответа
не пишет. После перезагрузки телефона сервер поднимается сам.

### 💬 Мобильный чат

- **Удержание сообщения** открывает меню: копировать, редактировать, продолжить, другой вариант,
  POV-кадр, портрет, перевод ⇄ оригинал, ветка, чекпоинт, удалить.
- **Свайп последнего ответа** влево — другой вариант, вправо — предыдущий.
- **💡 Варианты ответа:** три коротких хода («смело», «осторожно», «неожиданно») по-русски,
  отправляются по-английски. Тап — отправить, удержание — вставить в поле и поправить.
  Режим: выключено, по кнопке или автоматически после каждого ответа.

### ⚡ Власть персонажа

Персонаж может управлять сценой: настроение, погода, время суток, оттенок, частицы, эффекты
(удар, кровь, взрыв, молния, поцелуй, магия, сердцебиение, тряска), титры главы, глитч,
затемнение, шёпот. Он пишет невидимые метки `<!--stage ...-->`, приложение их исполняет.
Уровень «полный» разрешает ему ещё и заказывать картинки (POV или портрет). Уровни: выкл /
эффекты (по умолчанию) / полный, отдельно для каждого персонажа — в «Сцена и арт».

### 🧬 Генератор персонажей

Хаб → **Создать персонажа** (или `/forge`). Пишешь запрос («Рем из Re:Zero», «уставшая
наёмница в киберпанке») — получаешь готовую карточку: описание, характер, сценарий, первую
сцену и две альтернативные, примеры диалогов, теги и аватар. Канонных персонажей генератор
держит в каноне и меняет только то, что попросили; для картинок ставит их Danbooru-теги
персонажа и тайтла (Anima знает много фандомов). Перед созданием теги можно поправить.

### 📜 Пресет

`presets/Elephant-Tavern-Preset-v3.json` (v2 рядом) — пресет под приложение (Chat Completion → Импорт).
Автор-соавтор вместо «симулятора»: живые диалоги, темп по сцене, откровенные сцены без fade-to-black,
длина ответа переключается (короткий / средний / длинный), по-русски отдельным переключателем. v3: блок «Инициатива» — герой сам ведёт сюжет и пользуется своими способностями.

## Первый запуск

1. Установи APK (последний — во вкладке **Releases** или в артефактах **Actions**).
   Первый старт распаковывает SillyTavern (~320 МБ) — около минуты, дальше запуск за секунды.
2. На стартовом экране введи имя и ключ NanoGPT — подключение настроится само.
   Модели по умолчанию: текст `xiaomi/mimo-v2.6-pro`, картинки `anima/text-to-image`;
   поменять можно там же («Модели») или потом в хабе.
3. По желанию: **Сцена и арт** → **Служебная модель** — дешёвая модель для сцены, игрового
   режима, памяти и промптов картинок. Если пусто, используется основная.
4. **Игра** → игровой режим для чата.

Перенос с ПК: заархивируй папку `SillyTavern/data` в zip и выбери его в
**Приложение → Восстановить из бэкапа**.

## Сборка

Всё собирает GitHub Actions (`.github/workflows/build.yml`): каждый пуш в `main` даёт APK
в артефактах, тег `vX.Y.Z` — релиз.

Локально (JDK 17+, Android SDK 35, NDK 27.2, CMake 3.22, Node 20+):

```bash
./scripts/fetch-libnode.sh      # Node.js для Android (nodejs-mobile)
./tavern/build-bundle.sh        # SillyTavern + расширения → app/src/main/assets/tavern.zip
./gradlew assembleRelease
```

SillyTavern живёт в репо как обычный код. Новую версию upstream подтягивать по желанию:
слить её в `tavern/SillyTavern` и разрешить конфликты в перечисленных точках.

### Ключ подписи

Чтобы новые версии ставились поверх старых без потери данных, все сборки подписываются одним
ключом. Он не лежит в репозитории — Actions берёт его из секретов
(**Settings → Secrets and variables → Actions**):

- `SIGNING_KEYSTORE_B64` — keystore (PKCS12, alias `elephant`) в base64;
- `SIGNING_PASSWORD` — пароль к нему.

Без секретов APK собирается с временным debug-ключом (Actions предупредит), и такую
сборку придётся ставить начисто. Создать свой ключ:

```bash
keytool -genkeypair -keystore release.jks -storetype PKCS12 -alias elephant -keyalg RSA -keysize 3072 -validity 36500 -dname "CN=Elephant Tavern"
base64 -w0 release.jks   # → SIGNING_KEYSTORE_B64
```
